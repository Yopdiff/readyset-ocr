# 보안 점검 (2026-11-27)

## 이 앱이 다루는 정보
- **근무표 사진:** 사용자 이름뿐 아니라 **동료들의 이름과 근무 시간**이 들어 있어요.
- 직장 이름, 근무 일정, 알람 설정

이 정보는 **기기 밖으로 나가지 않아요.** iOS 앱에는 네트워크 코드가 없고, 글자 인식(Vision)도 기기 안에서 해요. 사진은 메모리에서만 쓰고 저장하지 않아요.

## 확인한 것 (문제 없음)
- 저장소에 비밀번호, API 키, 토큰 같은 비밀값이 없어요.
- 웹: 화면에 글자를 넣을 때 HTML로 해석하지 않아요 (`innerHTML` 없음). `npm audit` 결과 취약점 0개.
- iOS: `parser.js`에 OCR 결과를 넘길 때 코드에 끼워 넣지 않고 JSON 데이터로만 넘겨요. 그래서 사진 속 글자가 코드로 실행될 수 없어요.
- iOS: 사진은 `PhotosPicker`로 골라서, 사진 앨범 전체 접근 권한이 필요 없어요.
- iOS: 로그(`print`)에는 오류 내용만 찍고, 이름이나 근무 정보는 찍지 않아요.

## 고친 것
1. **캘린더 파일(.ics) 줄바꿈 주입:** 직장 이름에 줄바꿈 문자(CR 하나)가 들어가면 캘린더 파일에 가짜 일정이나 항목을 끼워 넣을 수 있었어요. 이제 모든 줄바꿈과 제어 문자를 막아요. 테스트도 추가했어요. (`web/parser.js`, iOS에도 동기화됨)
2. **웹 페이지 보안 정책(CSP):** 우리 파일만 실행되고, 외부로는 글꼴(Google Fonts)과 OCR 언어 데이터(jsdelivr)만 받을 수 있게 막았어요. 혹시 사진 속 글자가 HTML로 들어가도 코드를 실행하거나 데이터를 밖으로 보낼 수 없어요. 다른 사이트로 주소(referrer)도 보내지 않아요.
3. **웹 서버 노출:** README의 실행 명령이 같은 와이파이의 다른 기기에서도 접속되게 열려 있었어요. 이제 내 컴퓨터에서만 열려요 (`--bind 127.0.0.1`).
4. **iOS 개발자 메뉴:** Settings의 Developer 구역(샘플 데이터, 전체 삭제, OCR·알림 테스트 화면)이 출시 버전에도 들어갈 수 있었어요. 이제 디버그 빌드에서만 보여요 (`#if DEBUG`).
5. **클립보드:** OCR 테스트 화면의 "JSON 복사"는 동료 이름이 담긴 데이터를 클립보드에 넣는데, 다른 Apple 기기로 동기화되고 계속 남아 있었어요. 이제 이 기기에서만 쓰이고 2분 뒤 지워져요.

## 직접 결정해야 할 것
1. **커밋에 실제 이메일이 공개돼 있어요.** 이 저장소는 공개(public)이고, 커밋 기록에 학교 이메일과 Taylor의 Gmail이 남아 있어요.
   - 앞으로: GitHub 설정 → Emails → "Keep my email addresses private"를 켜고, 이 저장소의 `git config user.email`을 GitHub이 주는 `...@users.noreply.github.com` 주소로 바꾸세요. Taylor도 같이 하면 좋아요.
   - 이미 올라간 기록에서 지우려면 기록을 다시 쓰고 강제 push해야 해요. 둘 다 동의할 때만 하세요.
   - 저장소를 비공개(private)로 바꾸는 것도 방법이에요.
2. **잠금 화면 알림 내용:** 리마인더 알림에 직장 이름과 근무 시간이 보여요. 잠금 화면에서 숨기는 옵션을 고려해 보세요.
3. **GitHub 보호 설정:** `main` 브랜치 보호(PR 필수, 강제 push 금지)와 Dependabot 알림을 켜는 걸 추천해요.
